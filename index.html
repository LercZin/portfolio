Problems I have solved

Problemas que he resuelto

  • A store must never see another store's data.Store scope is enforced on the server, on every query and on creation, with tests that try to read another store's customer by ID.
  • Una tienda nunca debe ver los datos de otra.El ámbito de la tienda se aplica en el servidor, en cada consulta y al crear registros, con pruebas que intentan leer por ID un cliente de otra tienda.
  • A stock count that fails halfway must not leave half the stock adjusted.The whole count runs in one transaction with row locks, and is rejected if the balance changed since counting started.
  • Un recuento que falla a mitad no puede dejar medio inventario ajustado.Todo el recuento va en una transacción con bloqueo de filas y se rechaza si el saldo cambió desde que empezó.
  • Payment providers repeat notifications, sometimes before the charge exists.Each event is stored, applied once and replayed when the matching payment appears.
  • Los proveedores de pago repiten notificaciones, a veces antes de que exista el cobro.Cada evento se guarda, se aplica una sola vez y se reprocesa cuando aparece el pago.
  • A retried checkout must not charge twice.The checkout keeps one attempt key through network failures and stops instead of silently creating a new charge.
  • Repetir un checkout no debe cobrar dos veces.El checkout mantiene una única clave de intento ante fallos de red y se detiene en vez de crear otro cobro.
  • Tenant isolation should not depend on remembering a WHERE clause.PostgreSQL row-level security makes the database itself refuse another company's rows.
  • El aislamiento entre empresas no debería depender de acordarse de un WHERE.Con row-level security de PostgreSQL, la propia base de datos rechaza las filas de otra empresa.
